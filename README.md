# MyFlights — Flight Deal Monitor

כלי אישי לסריקת טיסות מישראל ליפן, קוריאה ותאילנד, עם עדכונים בטלגרם דרך GitHub Actions.

## מה הסורק עושה

- מבצע 6 חיפושי בסיס בהרצה רגילה: מסלול לכל יעד × חלון תאריכים. אימות נוסף של טיסת חזור נעשה רק למחירים שנראים כמו דיל, ומוגבל ל-4 בדיקות נוספות להרצה.
- ברוב הימים סורק טיסות הלוך־חזור מישראל; בערך בכל יום שלישי מבצע סריקות חד־כיווניות, כשהכיוון מתחלף בין ישראל לאסיה ובחזרה.
- מזיז את תאריך היציאה מדי יום בתוך כל חלון, ובוחר אורכי טיול שונים מתוך הטווח שהוגדר. כך הכיסוי מצטבר לאורך זמן במקום לבדוק שוב ושוב את אותם שלושה תאריכים.
- ממיין לפי מחיר, כולל תוצאות נוספות מוסתרות, ומסנן לפי עד 20 שעות ועד עצירה אחת לכל כיוון.
- מציג גם את המחירים הנמוכים שנמצאו כאשר אין דיל מתחת לסף, ומסמן בנפרד מחירים שלא הצליחו לעבור אימות של טיסת החזור.
- שולח סיכום לטלגרם בכל הרצה, גם כאשר לא נמצא דיל או כאשר ה-API נכשל.

## ספי מחיר (USD)

| מסלול | חד־כיווני | הלוך־חזור |
|---|---:|---:|
| ישראל ↔ יפן | $450 | $750 |
| ישראל ↔ קוריאה | $350 | $600 |
| ישראל ↔ תאילנד | $300 | $550 |

הספים נמצאים ב-routes_config.json וניתנים לשינוי. המחיר וזמינות הטיסות עשויים להשתנות עד פתיחת הקישור; יש לאמת את המחיר הסופי באתר Google Flights או חברת התעופה לפני הזמנה.

## הגדרה

ב-GitHub Repository → Settings → Secrets and variables → Actions, יש להגדיר:

- SERPAPI_KEY — מפתח SerpAPI
- TELEGRAM_BOT_TOKEN — הטוקן של הבוט
- TELEGRAM_CHAT_ID — מזהה הצ'אט שאליו שולחים

הפעולה מתוזמנת מדי יום ב-06:00 UTC, ואפשר גם להריץ ידנית בלשונית Actions → Flight Outlier Check → Run workflow.

## פרטי הסריקה

- פברואר 2027: אורך שהייה 7–14 ימים.
- 1 ביולי–10 בספטמבר 2027: אורך שהייה 10–21 ימים.
- מגבלות: עד 20 שעות ועד עצירה אחת.
- search_cycle_days: כל כמה ימים עוברים לסריקות חד־כיווניות.
- max_return_checks_per_run: תקרת אימותי החזור הנוספים, לשמירת מכסת ה-API.

הקבצים בתוך flight_tool/ נשמרים מסונכרנים לשימוש מקומי; ה-workflow רץ מהקבצים שבשורש המאגר.
